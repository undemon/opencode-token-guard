# Архитектура и решения

🇬🇧 [English version](DESIGN.md)

## Проблема

Типовая авария: движок отклоняет собранный запрос с `exceed_context_size_error`.
Причины — два независимых дефекта:

1. **Рассинхрон лимита.** `model.limit.context` может не совпадать с реальным
   окном движка (`n_ctx`): конфиг обещает больше, чем движок держит. Ядро
   считает порог компакции от `limit.context`, поэтому компакция срабатывает
   слишком поздно.
2. **Заниженная оценка токенов.** Ядро оценивает объём как `chars/4`
   (`core/src/util/token.ts`: `const CHARS_PER_TOKEN = 4`). На смеси кириллицы,
   кода и JSON реальное соотношение ≈ 2.8 симв./токен, то есть недооценка в
   ~1.4 раза. Ядро (`core/src/session/compaction.ts`,
   `splitConversation`/`recentStart`) при компакции может заморозить в чекпоинт
   `recent`, который по оценке числится «в пределах `keep.tokens`», хотя в
   реальных токенах он в разы больше. После этого любой запрос выходит за окно,
   а починить сессию компакцией уже нельзя — всё содержимое внутри
   замороженного `recent`.

## Что делает плагин

Три независимых кирпича:

| Модуль | Задача |
|---|---|
| `src/tokenizer/local.ts` | точный подсчёт через `@huggingface/tokenizers` |
| `src/guard.ts` | приведение собранного запроса к бюджету |
| `src/model-limit.ts` | синхронизация `limit.context` с окном движка |
| `index.ts` | регистрация хука `context` и трансформа модели |

### Почему хук `context`

Plugin API V2 **не даёт** заменить внутреннюю оценку токенов. Максимум доступного —
править собранный запрос в `session.hook("context", event => …)`, где доступны
`sytem`, `messages`, `tools`, `options` (мутируемые). Поэтому плагин не «чинит
формулу», а гарантирует, что отправляемый запрос укладывается в реальный бюджет.

### Порядок урезания

1. `<recent-context>` внутри `<conversation-checkpoint>` — отбрасывается его
   начало (самое старое), с пометкой
   `[token-guard: removed N characters of older context]`.
   Новейшая часть сохраняется.
2. Старейшие текстовые части, начинающиеся с `[Tool result]:` / `[Tool error]:`,
   заменяются короткой заглушкой.

Оценка «сколько символов снять» = `излишек_токенов × (символы/токены) × 1.15`,
после каждой правки запрос пересчитывается (до 8 итераций по чекпоинтам, затем
до 64 по результатам инструментов).

### Синхронизация лимита

`GET {backend}/api/v0/models` → `data[].loaded_context_length` (фактическое окно
движка) и `max_context_length`. Значение применяется через
`ctx.model.transform` (`editor.update(providerID, modelID, m => m.limit.context = …)`).
Раз в минуту окно перечитывается и при изменении вызывается `ctx.model.reload()`.

## Замеры (обоснование ресурсов)

Токенизатор целевой модели (`tokenizer.json` семейства Qwen3, 11.4 МБ), Python-биндинг `tokenizers` 0.23.3:

- загрузка словаря: +82 МБ RSS, 164 мс;
- скорость: 3.0 МБ символов/с (~500k токенов/с) в один поток;
- 380540 символов смеси → 134380 токенов за 119 мс;
- GPU/VRAM: **не нужна**.

`@huggingface/tokenizers` (то, что использует плагин) — чистый JS/TS, без
нативных зависимостей, ~8.3 КБ gzip. Порядок памяти и времени тот же.

## Проверенные факты о бэкендах

- **LM Studio** (OpenAI-совместимый API, порт по умолчанию 1234): эндпоинта токенизации нет ни в одной
  группе API. Неизвестные маршруты отвечают **HTTP 200** с телом
  `{"error":"Unexpected endpoint or method."}` — не путать с успехом.
- `GET /api/v0/models` отдаёт `state`, `max_context_length`,
  `loaded_context_length` — источник окна для `syncLimit`.
- **llama.cpp server** (`llama-server.exe`): `POST /tokenize`, `POST /detokenize`,
  `GET /props` (`default_generation_settings.n_ctx`) — база для режима `delegate`.
- **vLLM** — `/tokenize` есть, но нативно под Windows не работает. **Ollama** —
  публичного `/tokenize` нет.

## Открытые вопросы / план

1. **Асинхронный `TokenCounter`** — чтобы включить режим `delegate` и, при
   желании, «калибровку» оценки по факту (`prompt_tokens` из ответов LM Studio).
2. **Обрезка истории целиком** — не только `recent-context` в чекпоинте, но и
   удаление целых пар «запрос/ответ» при сильном превышении.
3. **Тест на реальной сессии** — прогон длинной сессии и сверка логов
   `[token-guard]` с фактическим `prompt_tokens` от LM Studio.
4. **Публикация** — после обкатки выложить на GitHub.
